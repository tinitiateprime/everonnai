# Website Studio code profile

This branch is a fresh Next.js 16.3.8 / React 19 application. The studio page is `/`; Business knowledge and Your designs are views of that page. Generated websites are served as standalone HTML at `/service/[business]/[version]`. It has no runtime dependency on the original app's accounts, database, restaurants, booking or skill registry. The assistant uses the existing ElevenLabs provider configuration through its own standalone integration.

## Routes and data

Voice/chat is adapted from the main project's website assistant without importing its database/booking/usage stack. `components/website-assistant.tsx` uses the ElevenLabs client SDK, session cleanup, transcript, microphone controls and Gemini fallback. `components/assistant-embed.tsx` embeds it beside studio previews. `lib/assistant.ts` selects the saved knowledge by business/version/revision, builds existing ElevenLabs dynamic variables, issues mode-specific conversation credentials and calls Gemini text reasoning. `lib/assistant-errors.ts` maps denied/missing/unavailable microphone conditions to actionable customer messages. `lib/assistant-embed.ts` adds a hashed, application-owned bootstrap to the served website while preserving original AI HTML/CSS. `app/assistant/[business]/[version]/page.tsx` serves the trusted widget frame.

Assistant routes: `POST /api/site-assistant/session` accepts business, version, artifact revision and voice/chat mode; it returns a transient ElevenLabs credential plus dynamic variables. `POST /api/site-assistant/message` accepts the same identity and bounded transcript; it sends server-selected knowledge to Gemini. Public website identity is readable, but browsers cannot substitute a knowledge packet or provider key. Both mutation endpoints retain same-origin and per-process rate checks. A stale artifact revision fails with a refresh instruction.

`lib/site-store.ts` creates safe business slugs and stable version 1–3 paths, saves generated artifacts atomically, and reads bounded stored records. `components/studio.tsx` shows each returned website path and an Open website link beside the HTML download. `app/service/[business]/[version]/route.ts` serves the original HTML directly with no studio layout.

Generated-site storage is runtime data rather than a deployment asset. The filesystem root lookup skips Turbopack tracing, and `next.config.ts` excludes local environment files, generated-site data and test artifacts from server output traces. New records include `knowledgeJson`, the exact generation evidence packet used by voice/chat; record reads are bounded to 8 MB. Older records remain readable as websites, but need regeneration for a known assistant snapshot.

| Route                | Input / output                                                                                               | External behavior                                                           |
| -------------------- | ------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------- |
| `GET /api/models`    | Current free model summaries and safe configuration booleans                                                 | OpenRouter model catalogue; five-minute process cache                       |
| `POST /api/discover` | `{url}` → newline-delimited progress/result/error events                                                     | Public source website, robots, sitemaps, source resources; no AI key needed |
| `POST /api/plan`     | Knowledge plus nullable discovery → three direction objects and successful model                             | OpenRouter chat completions                                                 |
| `POST /api/generate` | Knowledge/discovery, one direction, index, accepted artifacts and optional model ID → one validated artifact | OpenRouter, optional guarded browser asset requests                         |

Artifacts contain an ID/index, AI-selected name/rationale, complete HTML with original CSS, successful model, created time, warnings and optional token usage. Newly saved artifacts also carry `path`, the server-backed `/service/{slug}/{index+1}` URL. `POST /api/generate` persists accepted output before returning this artifact. `GET /service/[business]/[version]` reads the stored generated HTML without a provider call; absent businesses and missing/invalid versions return 404. Sources contain body evidence, contacts, assets, metadata, design cues and coverage. Knowledge enters AI as untrusted evidence; entered facts take precedence.

## Persistence and access

The browser uses IndexedDB `everonn-website-studio`, object store `drafts`, key `current`. It stores knowledge, discovery, plan, accepted artifacts and generation fingerprint. Knowledge drafts are not synchronized across devices. Each accepted artifact is also stored on the server under ignored `data/generated-sites/{slug}/{version}.json`, or `GENERATED_SITES_DIR`. Atomic temporary-file/rename writes preserve the previous successful file if saving fails. Same slug/version is the latest successful design; only that variant is replaced. Missing business names use a description-hash slug. Traversal paths and versions outside 1–3 are rejected. Stored records contain the generated artifact, slug, business name and exact website knowledge snapshot; they contain no provider credentials. Older browser-only designs acquire URLs when regenerated. Durable hosting requires a persistent writable volume shared by app instances.

The OpenRouter key is read exclusively from server-side `OPENROUTER_API_KEY`. ElevenLabs/Gemini keys are likewise server-only. There is no provider-key React state, input or outgoing browser header; the server ignores browser-supplied provider keys. Studio access tokens alone are held in React state/request headers and never persisted. API responses are private/no-store. Mutations require an Origin matching the incoming Host and HTTP/HTTPS protocol; the forwarded protocol supports HTTPS proxies, and invalid/missing/cross-site origins fail closed. This handles Next's internal localhost request URL without relaxing origin checks. The rate guard is local to one server process. There are no user accounts or tenant permissions. Production generation requires a configured studio token; local development requires one only when explicitly configured. Generated-site and widget GET routes are publicly readable without a studio token. The main generated document is script-free except for one exact hashed bootstrap; its only allowed frame is same-origin trusted assistant UI. The assistant frame has explicit script, same-origin, form and microphone permissions. Arbitrary model JavaScript remains blocked. Studio design-preview iframes remain opaque and script-disabled.

Environment variables: `OPENROUTER_API_KEY`, `OPENROUTER_MODELS`, `STUDIO_ACCESS_TOKEN`, `CHROMIUM_EXECUTABLE_PATH`, `GENERATED_SITES_DIR`. All are optional for opening the interface. A valid server provider key is necessary for real generation. `.env.local` is ignored; changes require a server restart. `OPENROUTER_MODELS` prioritizes available qualifying free IDs; blank uses Inkling, Laguna S 2.1 and Nemotron 3 Ultra, then eligible free alternatives. Catalogue checks reject missing or paid preferred models. Reasoning uses medium effort when advertised, otherwise another supported effort. Chromium installation is necessary for browser extraction/layout review; absence is reported and HTML discovery remains usable. `GENERATED_SITES_DIR` defaults to this checkout's `data/generated-sites` and must be writable and persistent for durable generated-site URLs.

## Completeness and verification

Additional environment variables: `ELEVENLABS_API_KEY`, `ELEVENLABS_AGENT_ID`, `GEMINI_API_KEY`, `GEMINI_ASSISTANT_MODELS`. Existing main-project values may be reused in the ignored local env file; no main provider configuration is changed. Voice/chat use the existing ElevenLabs agent template and dynamic placeholders. A compatible agent configuration and provider quota are required. Website generation remains on OpenRouter; assistant fallback uses Gemini, so visitor messages are not routed to the selected free website-generation models.

Assistant test coverage includes snapshot identity/source grounding, revision and business isolation, credential exclusion, Gemini fallback, fabricated booking-claim blocking, bootstrap hash/source validation, message entry, denied microphone permission, mobile sizing and model-script rejection. The optional live verifier uses fictional data and synthetic microphone input. The microphone/speaker experience on a real user device remains a separate check.

Runtime calls real public websites and OpenRouter; it has no demo/mock generation mode or fallback artifact. Test fixtures and provider mocks live only under tests/scripts. UI/API checks exercise fixtures and error paths; they do not establish live model quality. Generated output is a static single-document website, with functional in-page navigation and supported contact links, saved and served through its URL on this running server. There are no fake lead forms. External deployment, booking, payment, CMS and account backends are not implemented. Discovery limits and provider restrictions are described in README; aesthetic excellence is not automatically guaranteed by structural checks.
