# EverOnn Website as a Service

Standalone **Website Studio only**: AI generation, design preferences, three original designs, private previews, publishing, three-release rollback and HTML export. Includes the app, server API, client SDK, Dockerfile and database setup code. Bring your own database and provider keys; no customer data or secrets are included.

## 1. Run it

Node.js 22+ is required.

~~~bash
git clone --single-branch --branch waas-package https://github.com/tinitiateprime/everonnai.git
cd everonnai
npm ci
npm run setup
~~~

Edit the generated .env.local:

| Variable | What to add |
| --- | --- |
| WAAS_API_KEY | Already generated by setup; also used to sign in to Studio. Keep private. |
| GEMINI_API_KEY | Your Google Gemini API key with access and quota for the selected model. |
| WAAS_PUBLIC_URL | http://localhost:3000 locally; your exact HTTPS service origin in production. |
| DATABASE_URL | Your PostgreSQL connection string; required for normal production hosting. |
| PEXELS_API_KEY | Optional; add for stock photos. |
| GEMINI_WEBSITE_MODELS | Optional comma-separated model IDs available to your Gemini account. |

~~~bash
npm run dev
~~~

Open http://localhost:3000, sign in with WAAS_API_KEY, save verified business details, generate, review and **Approve & publish**. Builds pause when Studio closes; use **Resume saved build** to continue. Generation uses your provider quota/billing.

## 2. Add it to an existing site

**Fastest:** publish in Studio, copy the live URL, and add a link or iframe:

~~~html
<iframe src="https://studio.example.com/sites/your-business"
  title="Our website" style="width:100%;height:90vh;border:0"></iframe>
~~~

**Use your own hosting:** run the export example below and upload the resulting folder. It contains plain HTML/CSS with working relative navigation. Stock photos still load from Pexels.

~~~bash
node --env-file=.env.local examples/export.mjs SITE_ID ./exported-site
~~~

**Integrate generation into your app:** run npm run sdk:pack here, then install the generated everonn-waas-client-1.0.0.tgz in your client app. Call the SDK from your server, using WAAS_URL (this service's origin) and WAAS_API_KEY. [Working SDK example](examples/client.mjs) · [API reference](docs/API.md).

Booking, chat and voice buttons use the HTTPS action URLs you supply. If omitted, they become honest email/phone contact links. Client authentication, booking engines and conversational agents belong to the client's app.

## 3. Production

Set DATABASE_URL to **your database**, then:

~~~bash
npm run db:migrate
npm run build
npm start
~~~

Deploy on a Node.js host with request timeouts of at least 60 seconds. The migration creates only the private waas schema. Hosted PostgreSQL requires verified TLS; local PostgreSQL can use DATABASE_SSL=disable. Other settings are explained in [.env.example](.env.example).

Docker: build with docker build -t everonn-waas . and run with docker run --env-file .env.local -p 3000:3000 everonn-waas after migrating. No database container is bundled.

Development uses ignored local files automatically. For a single production server with a persistent disk, explicitly set WAAS_ALLOW_LOCAL_STORAGE=true and an absolute WAAS_DATA_DIR; use PostgreSQL for multiple instances/serverless. The API key grants access to all sites in this installation; authorize your customers in your own backend.

Checks: npm run check, npm run smoke (installed Chrome), npm run sdk:pack. Provider access and your deployed database/hosting must be validated in your environment.

Optional real provider check: npm run verify:live -- --live uses a fictional business and temporary files, makes paid Gemini/Pexels calls, then validates generation, publication and export without changing customer data.
