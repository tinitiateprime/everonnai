# Website Studio code profile

This branch is a fresh Next.js 16.3.8 / React 19 application. The studio page is `/`; Business knowledge and Your designs are views of that page. Generated websites are served as standalone HTML at `/service/[business]/[version]`. It has no runtime dependency on the original app's accounts, database, restaurants, booking or skill registry. The assistant uses the existing ElevenLabs provider configuration through its own standalone integration.

| Module                                       | Implemented responsibility                                                                                                                                                                                     |

## Routes and data

Voice/chat is adapted from the main project's website assistant without importing its database/booking/usage stack. `components/website-assistant.tsx` uses the ElevenLabs client SDK, session cleanup, transcript, microphone controls and Gemini fallback. `components/assistant-embed.tsx` embeds it beside studio previews. `lib/assistant.ts` selects the saved knowledge by business/version/revision, builds existing ElevenLabs dynamic variables, issues mode-specific conversation credentials and calls Gemini text reasoning. `lib/assistant-errors.ts` maps denied/missing/unavailable microphone conditions to actionable customer messages. `lib/assistant-embed.ts` adds a hashed, application-owned bootstrap to the served website while preserving original AI HTML/CSS. `app/assistant/[business]/[version]/page.tsx` serves the trusted widget frame.

Assistant routes: `POST /api/site-assistant/session` accepts business, version, artifact revision and voice/chat mode; it returns a transient ElevenLabs credential plus dynamic variables bounded to 48,000 bytes (`SESSION_VARIABLES_MAX_BYTES`) for the 64,000-byte WebRTC data-packet limit; owner facts stay complete and ranked crawled evidence is shortened first. `POST /api/site-assistant/message` accepts the same identity and bounded transcript; it sends server-selected knowledge to Gemini. Public website identity is readable, but browsers cannot substitute a knowledge packet or provider key. Both mutation endpoints retain same-origin and per-process rate checks. A stale artifact revision fails with a refresh instruction.

`lib/site-store.ts` creates safe business slugs and stable version 1–3 paths, saves generated artifacts atomically, and reads bounded stored records. `components/studio.tsx` shows each returned website path and an Open website link beside the HTML download. `app/service/[business]/[version]/route.ts` serves the original HTML directly with no studio layout.

Generated-site storage is runtime data rather than a deployment asset. The runtime website SKILL.md is explicitly included in plan/generate/refine server traces; a missing or invalid file fails generation rather than silently falling back to inline design instructions. The filesystem root lookup skips Turbopack tracing, and `next.config.ts` excludes local environment files, generated-site data and test artifacts from server output traces. New records include `knowledgeJson`, the exact generation evidence packet used by voice/chat, and `generationContext` with validated original knowledge/discovery for refinement; record reads/writes are bounded to 64 MB. Older records remain readable as websites, but need regeneration for a known assistant snapshot.

| Route                        | Input / output                                                                                                                 | External behavior                                                           |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------- |
| `GET /api/models`            | Current configured model summaries and safe configuration booleans                                                             | OpenRouter model catalogue; five-minute process cache                       |
| `POST /api/discover`         | `{url}` → newline-delimited progress/result/error events                                                                       | Public source website, robots, sitemaps, source resources; no AI key needed |
| `POST /api/plan`             | Knowledge plus nullable discovery → three direction objects with imageQueries, verified media bundles and successful model     | OpenRouter chat completions                                                 |
| `POST /api/generate`         | Knowledge/discovery, one direction, index, accepted artifacts, photo IDs and optional model ID → one validated artifact        | OpenRouter, optional guarded browser asset requests                         |
| `POST /api/site-pages/plan`  | `{business, version, revision}` → 1–4 planned inner pages `{slug, title, purpose}` chosen from saved knowledge/source evidence | Configured website provider (JSON)                                          |
| `POST /api/site-pages/build` | Revision, planned pages and `target` (a page slug, or `home` to add nav links) → updated artifact                              | Configured website provider; page merged into the saved record              |

Artifacts additionally store the original direction, approved photo metadata and last 20 accepted edit requests. Artifacts contain an ID/index, AI-selected name/rationale, complete HTML with original CSS, successful model, created time, warnings and optional token usage. Newly saved artifacts also carry `path`, the server-backed `/service/{slug}/{index+1}` URL. `POST /api/generate` persists accepted output before returning this artifact. `GET /service/[business]/[version]` reads the stored generated HTML without a provider call; `GET /service/[business]/[version]/[page]` serves a built inner page; absent businesses and missing/invalid versions return 404. Sources contain body evidence, contacts, assets, metadata, design cues and coverage. Knowledge enters AI as untrusted evidence; entered facts take precedence.

Multi-page sites ("Build full site"): artifacts may carry `pages` (`slug`, `title`, `purpose`, `html`, `model`, `createdAt`, `warnings`, `edits`) and a `designId` that stays stable across edits of one design and changes on regeneration. AI documents link pages with `page:<slug>` / `page:home` hrefs (optionally `#section`); validation only accepts slugs of the site's planned pages, and serving/preview/download rewrite them to `/service/{slug}/{version}/{page}`, preview URLs or `<page>.html` files, falling back to the home page for pages that were not built. Inner pages use subpage validation: invented contacts/images/executable content are still rejected, but every service and contact need not appear on every page. `saveSitePage` merges one page into the record under the per-file write lock and requires the saved `designId`; concurrent page builds and the home-link update therefore all persist, while pages from a regenerated (different) design are rejected. Home-page edits keep pages; regenerating a version drops them. Captions/labels attached to photos (link-free `<figcaption>`s and short link-free text alone beside an image) are removed at validation, at serve time and in the studio preview/download; linked photo credits stay.

## Persistence and access

The browser uses IndexedDB `everonn-website-studio`, object store `drafts`, key `current`. It stores incomplete knowledge, discovery, plan/media, accepted artifacts/edit history, unsent per-version change prompts and generation fingerprint. Knowledge drafts are not synchronized across devices. Each accepted artifact is also stored on the server under ignored `data/generated-sites/{slug}/{version}.json`, or `GENERATED_SITES_DIR`. Atomic temporary-file/rename writes preserve the previous successful file if saving fails. Same slug/version is the latest successful design; only that variant is replaced. Business names are now required for new generation; legacy description-hash slugs remain readable. Traversal paths and versions outside 1–3 are rejected. Stored records contain the artifact, slug, business name, exact website knowledge snapshot and original generation context; they contain no provider credentials. Older browser-only designs acquire URLs when regenerated. Durable hosting requires a persistent writable volume shared by app instances.

The OpenRouter key is read exclusively from server-side `OPENROUTER_API_KEY`. Pexels and ElevenLabs/Gemini keys are likewise server-only. There is no provider-key React state, input or outgoing browser header; the server ignores browser-supplied provider keys. Studio access tokens alone are held in React state/request headers and never persisted. API responses are private/no-store. Mutations require an Origin matching the incoming Host and HTTP/HTTPS protocol; the forwarded protocol supports HTTPS proxies, and invalid/missing/cross-site origins fail closed. This handles Next's internal localhost request URL without relaxing origin checks. The rate guard is local to one server process. There are no user accounts or tenant permissions. Production generation requires a configured studio token; local development requires one only when explicitly configured. Generated-site and widget GET routes are publicly readable without a studio token. The main generated document is script-free except for one exact hashed bootstrap; its only allowed frame is same-origin trusted assistant UI. The assistant frame has explicit script, same-origin, form and microphone permissions. Arbitrary model JavaScript remains blocked. Studio design-preview iframes remain opaque and script-disabled.

Environment variables: `PEXELS_API_KEY`, `OPENROUTER_API_KEY`, `OPENROUTER_MODELS`, `STUDIO_ACCESS_TOKEN`, `CHROMIUM_EXECUTABLE_PATH`, `GENERATED_SITES_DIR`. Secrets stay server-side; `.env.local` is ignored and requires restart after changes. `OPENROUTER_MODELS` is an ordered allowlist; blank defaults to `~anthropic/claude-opus-latest,~google/gemini-pro-latest,openai/gpt-6.1-sol`. Latest Claude/Gemini aliases without `~` are normalized. Catalogue checks skip missing/ineligible IDs and never add models outside the list. Paid generation is enabled and billed by OpenRouter; a funded server key is required. Supported medium reasoning is preferred; otherwise a supported effort, 3,000-token budget or default is used. Optional reasoning without advertised controls is disabled. Chromium supplies optional browser extraction/layout review. `GENERATED_SITES_DIR` defaults to `data/generated-sites` and needs writable persistent storage.

## Completeness and verification

Additional environment variables: `ELEVENLABS_API_KEY`, `ELEVENLABS_AGENT_ID`, `GEMINI_API_KEY`, `GEMINI_ASSISTANT_MODELS`. Existing main-project values may be reused in the ignored local env file; no main provider configuration is changed. Voice/chat use the existing ElevenLabs agent template and dynamic placeholders. A compatible agent configuration and provider quota are required. Website generation remains on OpenRouter; assistant fallback uses Gemini, so visitor messages are not routed to the selected website-generation models.

Assistant test coverage includes snapshot identity/source grounding, revision and business isolation, credential exclusion, Gemini fallback, fabricated booking-claim blocking, bootstrap hash/source validation, message entry, denied microphone permission, mobile sizing and model-script rejection. The optional live verifier uses fictional data and synthetic microphone input. The microphone/speaker experience on a real user device remains a separate check.

Runtime calls real public websites and OpenRouter; it has no demo/mock generation mode or fallback artifact. Test fixtures and provider mocks live only under tests/scripts. UI/API checks exercise fixtures and error paths; they do not establish live model quality. Generated output is a static single-document website, with functional in-page navigation and supported contact links, saved and served through its URL on this running server. There are no fake lead forms. External deployment, booking, payment, CMS and account backends are not implemented. Discovery limits and provider restrictions are described in README; aesthetic excellence is not automatically guaranteed by structural checks.

## Runtime instructions, photography and editing

- `ai/capabilities/website-building/SKILL.md` contains the active application generation/refinement instructions; `lib/website-skill.ts` reads it per operation. No domain skill registry or prebuilt website layouts are imported. The required asset is explicitly traced into deployment output for the three generation routes.
- `lib/pexels.ts` uses server-only `PEXELS_API_KEY` for fixed Pexels search/photo endpoints, bounds and verifies HTTPS image/credit hosts, caches metadata for 24 hours with bounded caches, and deduplicates concurrent searches. Planning queries are AI-created generic subjects, one or two per direction, without private business identifiers. Each media bundle includes up to eight candidate photos plus warnings.
- `POST /api/generate` accepts photo IDs and resolves their exact URLs/credits server-side. AI receives skill + knowledge/evidence + direction + approved assets. Validation allows only supplied image URLs, requires Pexels/photographer credits for used stock images, and viewport inspection checks credit visibility when available. Image placement and CSS remain AI-authored.
- `POST /api/refine` accepts `{business,version,revision,prompt,model?}`; knowledge, HTML, photo credits and history are loaded from the stored version, never accepted from the browser. It uses the same provider/validation/browser checks as generation. Returned artifacts have a new revision, same version path, original knowledge snapshot and last 20 accepted edit requests. Other versions are unchanged. The prompt is capped at 6,000 characters; missing/incompatible older context requests regeneration. Stale revisions return HTTP 409 before inference or at save time with the latest artifact; the studio loads it and retains the typed prompt for review/retry.
- Writes and revision comparisons are serialized per file in one Node process, followed by atomic replacement. Across processes there is no distributed edit lock; a single writer instance is needed for conflict protection. Older sites lacking generationContext/direction can still be read and can enable prompt editing through regeneration from complete knowledge.
- Incomplete knowledge and unsent per-version prompt drafts are stored in IndexedDB; accepted changes are also stored in the server artifact. Editing business facts requires changing knowledge and regeneration. Regeneration starts a new design/history; refinement preserves the saved facts for voice/chat.
- `scripts/verify-website-live.ts` is an explicit Pexels/OpenRouter probe with fictional knowledge and temporary storage, independent of routine mocks. `--media-only` checks Pexels without an AI key; `--all` additionally generates three websites and edits one. `@next/env` is a direct dependency for this environment-loading script.

A key is now configured locally. Live provider checks established authentication and real AI planning; the first full-generation attempts timed out. Follow-up generation evidence is reported below. Earlier live assistant verification remains separate.

## Assistant connection reliability

`lib/assistant-connection.ts` bounds pending ElevenLabs SDK connections to 45 seconds and observes cancellation. The SDK's start operation cannot be cancelled directly; any connection which resolves after close/timeout is immediately ended. `components/website-assistant.tsx` invalidates stale callbacks after disconnect or failed initialization, clears microphone/reply state, and retains a typed message if sending fails. This prevents delayed connections from reopening a closed widget or overwriting fallback/ended state. Existing assistant endpoints, credentials, knowledge snapshots and generated HTML/CSS remain the same.

The explicit live verifier now opens all three generated service URLs, checks both launchers, exercises real ElevenLabs text and voice, verifies remote audio playback, mute/end/reconnect, and tests real Gemini fallback against the saved snapshot. `--speech` creates an English Windows speech WAV in verified temporary test storage through `scripts/make-assistant-test-audio.ps1`; `--audio=/path/question.wav` accepts a supplied WAV on other platforms. The spoken question asks about fictional Saturday hours and wheel truing; recognition and the grounded voice answer are checked. These provider calls use quota and run separately from routine mocks. Physical microphones/speakers and all browsers/networks are not covered by this synthetic-device test.

On 2026-10-09, the live generated-site check verified both controls on versions 1?3, real ElevenLabs chat answers, a synthetic spoken microphone question with a knowledge-grounded voice answer, incoming audio playback, mute/end/reconnect, and real Gemini fallback. Synthetic devices verify the integration; physical microphone/speaker quality still needs a real-device check.

## Large-site discovery

`lib/crawl-limits.ts` supplies a 500-page initial limit, a 2,000-page hard ceiling, 40-page/75-second batches and four parallel reads (configurable within bounds). `lib/discovery-store.ts` saves atomic crawl checkpoints with their URL frontier/visited set, enforces same-process crawl ownership, stores immutable generation snapshots and bounds records to 64 MB. Files use random UUID names under ignored data/crawls or CRAWL_STORAGE_DIR; a persistent writable volume and a single writer process are required for durable continuation. Source records contain public captured evidence, never provider keys.

`POST /api/discover` accepts URL, optional crawlId, capturedCount, extend flag and legacy browser discovery. It streams incremental checkpoint pages and a completion descriptor, not the entire growing crawl on every batch. Checkpoints recover pages received by the server while the browser disconnects. Continue discovery resumes the cursor; Read more pages increases the same crawl limit up to 2,000. Pause/cancel retains saved progress. The client automatically requests successive batches while active; it resumes after refresh when Continue is clicked. Closing the browser pauses the work; this is not a continuously running background worker.

The crawler retains public-address/DNS/redirect checks, robots restrictions and source URL evidence. It renders the first page for design cues and short JavaScript app shells; substantive static HTML pages avoid repeated Chromium rendering. Positive robots delays serialize reads. Long requested delays stop further reading with a warning.

Plan/generate inputs can reference discoveryId/sourceSnapshotId instead of uploading the growing raw crawl repeatedly. Planning freezes a snapshot; all three generation calls load that same immutable source. Generated artifacts retain the matching snapshot/knowledge for refinement and voice/chat. `lib/source-context.ts` compacts sources above 40 pages: it prioritizes up to 80 business pages, deduplicates contacts from the entire crawl (1,000 per type maximum, within a 15,000-character budget per type), and bounds the source index to 60,000 characters and detailed page records to 100,000 characters. Raw captured evidence remains in crawl/snapshot storage and browser review; AI context coverage/truncation is explicit. Legacy discoveries up to 40 pages retain their original packet shape.

Additional server variables: `CRAWL_MAX_PAGES`, `CRAWL_BATCH_PAGES`, `CRAWL_BATCH_SECONDS`, `CRAWL_CONCURRENCY`, `CRAWL_STORAGE_DIR`. Deployment traces exclude crawl data. Discovery defaults to 500 pages and can expand to 2,000. Website output allows up to 12,000 tokens including reasoning, bounded by the selected model; instructions target approximately 6,000 visible tokens. Plans allow 5,000 tokens. Provider/hosting time limits remain possible; accepted files and saved source checkpoints survive partial failures. No static generation fallback is added.

Reasoning controls follow catalogue capabilities, preferring medium effort where advertised. Document repair feedback identifies missing/unsupported elements. Obsolete X-UA-Compatible metadata is removed without changing AI layout/CSS. Photo-credit viewport checks normalize whitespace consistently with structural validation. The explicit website verifier supports `--resume` and `--model=ID`, retaining only ignored fictional-business artifacts; running it consumes configured OpenRouter credits.

The public catalogue confirmed Claude/Gemini/GPT IDs and capabilities on 2026-10-09. No test, build or live-generation runs were performed after the owner requested skipping tests. Earlier free-model attempts did not validate accepted live website output under this configuration.
